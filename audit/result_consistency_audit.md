---

## 2. Root Cause: Lack of Provenance Tracking

1. **No Single Source of Truth**: Different scripts compute "hybrid accuracy" using two distinct definitions:
   - *Definition A*: Accuracy strictly over samples flagged as anomalies by the Autoencoder (`y_test_anomalies`).
   - *Definition B*: End-to-end accuracy over the entire test set (`overall_pred`), where samples below the threshold are classified as Benign/Normal and samples above are classified by XGBoost.
2. **Missing Experiment Hash Linkage**: Metric files lack metadata tracking Git commit SHA, dataset version hash, random seed, or split hash.
3. **Dashboard Fragility**: The Streamlit dashboard attempts to load whichever JSON is present in `result_images/`. If an intermediate script partially completes, the dashboard displays "No results found" or stale historical metrics.

---

## 3. Resolution Plan

1. Archive all old conflicting metrics into `results/archived/DO_NOT_USE_FOR_PAPER/`.
2. Institute a unified `ResultRegistry` in `results/result_registry.json`.
3. Standardize mathematical definitions:
   - $\text{Stage 1 (AE)}$: Binary Anomaly Detection (Accuracy, Precision, Recall, F1, FPR, FNR, ROC-AUC).
   - $\text{Stage 2 (XGBoost)}$: Multi-Class Classification on anomalous traffic subset.
   - $\text{End-to-End System (Hybrid)}$: Macro-F1, Weighted-F1, Overall Accuracy, and per-class metrics over the full test partition.
